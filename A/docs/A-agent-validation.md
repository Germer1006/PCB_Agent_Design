# A 模块智能体能力检查

## 交付对象与当前边界

交付对象是 A 系统设计智能体及其工具链。5 V→12 V/0.5 A 的 r6 是验证案例；采购、焊板和整机实测属于案例的后续验证，不是继续开发 A 智能体的前提。

当前已实现的是 MCU 数字 CC/CV 非同步 Boost 流程。需求和主要数值可参数化，但缺少其他电路类型的计算模型、选型规则和验证集，尚不能称为任意 PCB 的通用系统设计智能体。技能指令负责让模型理解需求、决策、解释与回溯；Python 工具负责计算及检查，单独跑脚本不等于验证了模型编排能力。

## 本次修正

1. 合并 T1/T3/T4 后，T3 一致性测试重新生成带 T4 元数据的检查结果，不再把旧格式检查文件当作新结果。成功路径使用明确标记的合成供电夹具；真实器件库未添加虚构 max 值。
2. 选型无候选时返回 2，停止后续损耗/环路，保留各候选淘汰理由。无效或不合格的显式 override 保持失败，未知 override 类别也会报错。
3. 不支持的拓扑、非法基础数值、不满足升压条件和标准电感列表不够时，明确拒绝并输出 `calc_error.json`，避免无说明的算术异常。
4. SDRC 返回 2/3 时仍保留账本用于定位原因，随后停止导出；环路独立复核使用一键流程指定的同一份器件库。

## 需求变体结果

命令：`python A/eval/run_eval.py --output A/outputs/eval_preflight_new`。输出目录必须新建，避免覆盖旧失败。结果见 [eval/results.md](../eval/results.md) 和机器可读快照。

12 组均满足此回归的行为断言：5 组完成初算与初选、6 组缺匹配器件停止、1 组不满足升压条件被拒绝。固定默认策略下，三组低电流需求初算 L_req 为 111.2/125.0/116.8 µH，可用且证据合格的电感候选覆盖不足；4.5→15 V/0.8 A 又受更高 Isat 需求等限制。不能把缺件当作物理不可行，也不能把“5 组完成选型”写成“5 个设计已合格”。

## 完整工具流程复跑

两组均运行 `python A/.agents/skills/boost-system-design/scripts/run_all.py A/outputs/test_agent_<id>`，使用真实器件库、全量环路搜索和完整仿真矩阵，没有用测试夹具代替器件证据。`r6` 复制原有需求与决策，仅升级 revision 为 `r6-agent-eval1`；`easy03` 使用评测输入及默认决策、revision 为 `eval-easy03`。机器可读结果与输入/输出指纹见 [end_to_end_summary.json](../eval/end_to_end_summary.json)，原始 JSON/CSV/SVG 保留在上述本地输出目录。

r6 完成计算、初选、损耗、环路、独立复核、仿真、SDRC 和账本，因关键证据缺失停止在导出之前：

- 仿真 58 工况：54 PASS、4 WARN、0 FAIL；4 项 WARN 是未加独立输入缓升的冷插电线性模型结果。额定点和最坏纹波的 4 项交叉验证均通过；仿真耗时 709.95 s。
- SDRC：85 PASS / 8 WARN / 0 FAIL / 2 NOT_ASSESSED / 1 N/A，`needs_rework`。SR70/SR71 仍缺 LDO dropout.max 或输入路径电阻 max，不能由典型值补齐。
- 来源账本 80/80 步；未生成 `design_spec.json`。剔除 steps、revision 和新增选型状态字段后，calc/selection/losses/loop 与原 r6 数据相同。
- `check_design.py` 原生退出码单独捕获为 3；PowerShell 工具把原生非零退出统一呈现为 1（用 `sys.exit(3)` 已复核）。代码和门禁测试确认一键流程在账本后传播原始门禁码。

easy03（5.5 V→9 V/0.5 A）同样完成至账本，未导出交接：

- 环路独立复核 PASS；仿真 81 工况为 75 PASS、6 FAIL，另保留 4 个未加保护的直插 WARN 对照。独立输入缓升 27/27 通过，但配置明确为 `proposed_requires_hardware`，不是已实现或实测的保证；仿真耗时 616.13 s。
- SDRC：86 PASS / 7 WARN / 1 FAIL / 2 NOT_ASSESSED / 0 N/A，`needs_rework`，检查器原生退出码 2。失败规则 SR87 对应过流场景，SR70/SR71 的供电证据仍缺失；账本 80/80 步。
- 失败定位：当前 `S-ocp` 假定负载变到 `R_rated/3` 后也不应触发保护。该规格 R_rated=18 Ω，实际施加 6 Ω，而工具给出的恒流可控下限为 13.55 Ω；仿真波形显示关断后电流约 0.75–0.83 A，仍高于软件阈值 0.6 A，因而 4 个工况在 10 ms 后执行软件保护，却不满足原来的“不触发”预期。`S-ocp__sw_trip` 再变到 4.5 Ω 时，标称/高输入的滤波电流峰值约 1.048/1.106 A，超过 1.0 A 硬件阈值，硬件先于软件动作，形成另外 2 项预期不符。
- 这暴露的是固定负载比例/固定预期在新需求下的测试适用性缺口，不能直接推断控制器误触发，也不能据此宣布方案通过。本次保留原始失败与判据，没有把提前硬件保护改判为软件保护通过；下一步应先明确每个测试的有效负载区间和阈值前提，再生成可区分正常恒流、软件延时和硬件快断的激励，并保留超出可控区的故障对照。

## 后续推进顺序

1. 先修正 T1 过流场景的参数化与前提检查，区分测试预期不适用、控制未达标和供电证据缺失；保留本次失败作为回归样例。对缺件规格回溯 S5/S6：先检查可调整的内部决策，再查证扩充有代表性的电感、耐压与保护器件。保留调整理由，重跑全部下游检查，不改需求凑通过。
2. 对完成初选的变体补完整 S7–S9，保留环路、仿真及规则失败；形成覆盖需求变化、缺证据和失败回溯的端到端样例。
3. 建统一答案结构、提取器与评分器，再在隔离上下文中跑同模型 C0–C3，保存完整回答，统计全部失败。当前脚本结果不能代替这一步。
4. 如需扩展到 Boost 以外的 A 系统设计任务，先增加相应拓扑模型/知识与测试，再放宽技能的能力声明。

开发效率方面，本机两组完整运行的环路搜索各约 14–15 分钟，时域仿真还需逐工况运行。后续可缓存与控制器候选无关的模型/频率响应，并给 `run_all.py` 增加子阶段实时进度；加速后需核对数值一致性，不能缩减容差覆盖来提高通过率。本次未改搜索算法或仿真矩阵。

现在不需要用户采购器件或替智能体决定电感、阈值等工程参数。只有课程任务边界、是否做实物、装配/预算偏好等真实约束不明确时才向用户询问。
