### T1　开关级时域仿真（`scripts/sim_switching.py`）

**为什么做**
现有 S7 只用平均小信号模型，只能证明 CCM 小扰动稳定。8 项 WARN 中 SR65（DCM/空载/CC-CV 切换）、部分 SR53（上电浪涌）只能靠时域仿真或实测关闭。
文献依据：Nau 等（ACM TODAES 2026, arXiv:2507.10639）在 269 个开关电源任务上，加入仿真工具后成功率由 44 % 升至 85–91 %；纹波类任务仅靠手册公式无法可靠完成。

**做什么**
写一个**纯 Python、逐开关周期**的 Boost + 数字控制器仿真器，复现固件实际行为，跑若干场景，输出可量化指标。

1. **功率级模型**（每个开关周期内分段积分，步长 ≤ 50 ns，可用 RK4 或解析分段解）
   - 状态：电感电流 iL、各输出电容电压（与 `stage_params.build()` 的 `caps` 列表一致：陶瓷支路、储能支路，各带 ESR）。
   - 开关导通：`L·diL/dt = Vin − iL·(DCR + Rds + 输入通路电阻)`；二极管截止。
   - 开关关断：二极管导通，压降 `VF0 + Rd·iL`；**iL 降到 0 时二极管截止，iL 保持 0（DCM）**——这是平均模型做不到的关键点。
   - 输出节点：并联电容支路 + 负载。负载类型：恒阻（CR）、恒流（CC，电子负载）、阶跃（切换）。
   - 参数来源：直接调用 `stage_params.build(selection, db, calc, choices, factors)` 得到 L、DCR、Rds、VF0、Rd、caps，保证与 S7 一致；容差场景用 `variants()`。
2. **控制器模型**（严格按 `design_spec.json → control` 与 `boost_params.h`）
   - PWM：fsw = 100 kHz，计数 ARR+1 = 1700，占空比按计数量化，`CCR ≤ PWM_CCR_MAX`；新占空比在下一个 PWM 周期生效。
   - 采样：每个控制周期（RCR+1 = 5 个 PWM 周期）在导通区间中点采样一次 Vout、Iout；经 RC 滤波（电压分压 RC、电流 1 kΩ/10 nF + 放大器极点）后按 12 位 ADC 量化（`VOUT_V_PER_CODE`、`IOUT_A_PER_CODE`）。
   - PI：`u = Kp·e + I`，`I += Ki·Ts·e`；CV、CC 两环并行，输出取小，再限幅到 `[DUTY_MIN, DUTY_MAX]`；**非主导环积分跟踪**：`I = d_actual − Kp·e`（与 `control.structure` 描述一致）。
   - 软启动：参考值从启动时的 Vout 以 `SOFTSTART_MS` 斜坡升到 12 V。
   - 保护：软件 OVP/OCP/UVLO 按 `boost_params.h` 阈值与延时，触发后 PWM 关闭并锁存；硬件 OVP/OCP 用逐周期比较（触发后当周期关断并锁存）。
3. **场景**（每个场景在 Vin = 4.75 / 5.0 / 5.25 V 下各跑一次；关键场景再跑最坏容差场景）

   | 场景 | 设置 | 输出指标 |
   |---|---|---|
   | S-start | 0 时刻使能，负载 CR 24 Ω，仿真 40 ms | 上升时间、过冲 %、调节时间（±2 %）、启动期间 iL 峰值 |
   | S-steady-CV | 稳态，CC 负载 0.1/0.25/0.45 A | Vout 均值误差 %、纹波 Vpp 与 %、是否 DCM |
   | S-steady-CC | 稳态，CR 12.5/18/22 Ω | Iout 均值误差 % |
   | S-step | CR 48 Ω → 24 Ω → 48 Ω（各保持 10 ms） | 欠冲/过冲、恢复时间 |
   | S-handover | CR 30 Ω → 16 Ω（CV→CC）→ 30 Ω（CC→CV） | 切换瞬间 Vout/Iout 过冲、是否振荡、主导环切换时刻 |
   | S-light | CC 负载 0.02 A 与空载（只有分压电阻） | DCM 下 Vout 是否稳定、是否出现极限环（输出电压周期性波动幅度） |
   | S-ovp | 稳态 CV 时负载突然断开 | Vout 峰值 vs 硬件 OVP 13.8 V 与 TVS VBR 16.7 V；是否锁存 |
   | S-ocp | CR 逐步降到 8 Ω | OCP 动作时间与锁存；iL 峰值 vs 电感 Isat 3.6 A |
   | S-plugin | 无 PWM，Vin 0→5.25 V 阶跃（模拟插电） | 输出电容被动充电峰值电流（与 losses.json `inrush` 线性估计对照） |

4. **输出**：`sim.json`（每个场景的指标、通过/不通过、所用参数版本）、`sim_<场景>.csv`（降采样波形：t, vin, iL, vout, iout, duty, mode）、`sim_waveforms.svg`（可复用 `svgplot.py` 风格画时域图）。
5. **与平均模型交叉验证**：在 S-steady-CV 额定点，仿真得到的占空比均值、iL 均值与 `losses.json → cases.nom` 的 D、IL_avg 偏差应 < 2 %；纹波与 `ripple.vpp_harmonic_mv` 偏差应 < 20 %（ESL/采样差异）。不满足时先排查仿真器。
6. **接入流程**：`run_all.py` 在 `validate_loop.py` 之后加 `sim_switching.py`；`check_design.py` 新增规则：
   - `SR80` 启动过冲 < 10 %，无锁存误触发；`SR81` 稳态 CV/CC 误差 < ±5 %（课程要求）；`SR82` 纹波 < 5 %（硬性）/ < 3 %（建议，WARN）；`SR83` CV↔CC 切换无持续振荡；`SR84` DCM/空载稳定（无幅度 > 1 % Vo 的极限环）；`SR85` OVP 场景 Vout 峰值 < TVS VBR,min。
   - 仿真通过后，SR65 的说明改为“已由开关级仿真覆盖 X 个场景，仍需实测”，状态保持 WARN（仿真 ≠ 实测）。
7. **性能**：单个 40 ms 场景在普通笔记本上应 < 30 s；全部场景 < 5 min。可通过每周期解析分段解（导通/关断段为一阶/二阶线性系统）提速。

**验收标准**
- [ ] `python sim_switching.py <wd>` 在基线设计上跑完所有场景，生成 `sim.json`、CSV、SVG。
- [ ] 第 5 条交叉验证通过。
- [ ] 单元测试：①开环固定占空比、无损时稳态 Vout ≈ Vin/(1−D)（误差 < 1 %）；②轻载时 iL 出现 0 段（DCM 被正确模拟）；③PI 积分跟踪：非主导环积分值满足 `I = d − Kp·e`。
- [ ] SDRC 新规则生效；若有场景不通过，如实报告并回到 SKILL.md 回溯表对应阶段处理，**不得改判据凑通过**。
- [ ] 报告模板 `report_outline.md` §7 增加“开关级仿真”小节，说明模型范围与局限（理想开关沿、无寄生电感、无温度效应）。

### T2　消融实验与评测集（`eval/`）

**为什么做**
课程考核“智能体”本身，参考论文用消融实验（有/无分层架构、有/无 RAG）证明方法有效。我们需要同样的定量证据：**完整 skill 相对“只用大模型”到底好在哪里**。文献中常用指标：任务成功率（±5 % 内算成功）、pass@k、器件违规数、仿真通过率。

**做什么**

1. **评测集** `A/eval/specs/*.json`：在课程规格周围做 12 组变体，格式与 `inputs/course_requirements.json` 相同：
   - Vin：4.5 / 5 / 5.5 V（容差 ±5 %）；Vout：9 / 12 / 15 V；Icc：0.3 / 0.5 / 0.8 A；纹波上限 3 % / 5 %。
   - 选 12 组覆盖“容易 / 典型 / 困难”（困难如 5 V→15 V/0.8 A，占空比与电流应力大）。
   - 至少 1 组**不可行**规格（如 Vin_max ≥ Vout），正确行为是拒绝并说明原因。
2. **标准答案** `eval/ground_truth/*.json`：由确定性工具生成——对每组规格跑 `run_all.py`，提取关键量：D（Vin_min）、Iin、L 需求、Isat 需求、Cout 有效需求、MOSFET/二极管应力、CC 下限、保护阈值。这些是“正确答案”。
3. **四种配置**（同一个大模型，例如 Codex 所用模型）：

   | 配置 | 允许使用 |
   |---|---|
   | C0 只用大模型 | 只给规格文本，要求输出设计答案；不加载 skill、不允许运行脚本 |
   | C1 + 计算工具 | 可运行 `calc_boost.py`，但无器件库（器件凭模型知识选） |
   | C2 + 器件库 | C1 + `parts_db.json` + `select_parts.py` |
   | C3 完整 skill | 加载 skill，全流程（含 S7–S9；T1 完成后含仿真） |

4. **统一答案格式** `eval/answer_schema.json`：每次运行输出 `answer.json`，包含关键参数（D、L、Isat、Cout、器件型号与立创编号、Dmax、保护阈值、Kp/Ki）。C0/C1 由模型按此格式填写；C2/C3 由脚本从工作目录提取（写 `eval/extract_answer.py`）。
5. **评分脚本** `eval/score.py <answer.json> <ground_truth.json> <parts_db.json>`，输出：
   - **参数正确率**：每个关键量与标准答案相对误差 ≤ 5 % 记为正确；
   - **器件有效率**：型号存在于器件库且立创编号一致的比例（C0/C1 若器件不在库中，标为“无法核实”——这正是幻觉风险的量化）；
   - **额定值违规数**：对答案中的器件，用 `select_parts.py` 的硬性规则检查耐压/电流/Isat 等，统计违规条数；
   - **Critical 规则命中数**：对 C2/C3 用 `check_design.py`（依赖 T4 的严重度）；
   - **不可行规格处理**：是否正确拒绝。
6. **重复性**：每组规格 × 每种配置跑 3 次，报告均值与 pass@1、pass@3（至少一次全对）。C0/C1 需人工在 Codex 中运行并保存答案，**保存完整对话或输出记录**以备核查。
7. **汇总** `eval/run_eval.py` → `eval/results.md`：一张总表（4 配置 × 指标）+ 一张失败案例表（列出 C0/C1 的典型错误，如“输出电容耐压 16 V 用于 12 V 输出且未计降额”“二极管电流额定低于电感峰值”“编造的立创编号”），这两张表直接用于报告与答辩。

**验收标准**
- [ ] 12 组规格 + 标准答案入库；`score.py` 对标准答案自身打分为 100 %。
- [ ] 4 配置 × 12 规格 × 3 次的原始答案全部保存在 `eval/runs/`，可复评。
- [ ] `results.md` 含总表、失败案例表、方法说明与局限（样本小、单一模型、计算值非实测）。
- [ ] 不挑选结果：所有运行都计入统计；失败的运行同样保留。

### T3　计算依据账本与一致性校验

**为什么做**
评分点“参数计算与器件选择有依据”。现在 `calc.json → steps` 记录了公式与代入值，但**输入从哪里来**（哪条需求、哪个器件的哪页参数、哪个设计决策）没有结构化记录；换器件后哪些数过期也无法自动判断；报告、`design_spec.json`、BOM、`boost_params.h` 之间的数值一致性靠人工保证。
参考：jvanderberg/kicad-skills 的规则 R25（每个推导值记录公式与每个输入的来源，换件后列出过期值）。

**做什么**

1. **扩展 `_common.Steps`**：`add()` 增加 `inputs` 参数，每个输入记录来源：
   ```json
   {"id": "L1", "name": "电感量需求", "formula": "...", "value": 70.08, "unit": "µH",
    "inputs": [
      {"name": "Vin", "value": 5.25, "source": "req:vin.nom_v×(1+tol)"},
      {"name": "r",   "value": 0.35, "source": "choice:power_stage.inductor_ripple_ratio"},
      {"name": "eta", "value": 0.85, "source": "choice:power_stage.eta_assumed"}]}
   ```
   来源前缀统一为：`req:`（requirements.json 路径）、`choice:`（design_choices.json 路径）、`part:<id>.<param>@<page>`（parts_db）、`step:<id>`（其他计算步）、`const:`（物理常数或标准值表）。
   改造 `calc_boost.py`、`loss_model.py`、`loop_design.py` 中所有 `S.add()` 调用，补齐 `inputs`。
2. **账本导出** `scripts/ledger.py <wd>` → `ledger.json` + `ledger.md`：汇总所有步骤，生成依赖图（step → inputs）；`ledger.md` 给报告用，按“需求 → 计算 → 器件 → 规则 → 测试”排成**计算依据表**。
3. **过期检测** `ledger.py <wd> --stale <part_id|choice_key>`：列出受影响的全部计算步、规则与交接字段。例：`--stale L_MWSA1206S_680MT` 应列出纹波、损耗、环路、SR34/36/37/38 等。
4. **一致性校验** `scripts/check_consistency.py <wd>`：
   - `design_spec.json`、`bom_module1.csv`、`boost_params.h`、`report_tables.md` 中的关键数值（PWM_ARR、CCR_MAX、各换算系数、Kp/Ki、保护阈值与码值、器件型号与立创编号、CC 范围）与 `calc/selection/loop/check.json` **逐项比对**，任何不一致报错；
   - 所有文件的 `revision` 一致；
   - 报告正文中引用的关键数字：约定报告用 `{{calc:L2}}`、`{{loss:envelope.eta_min}}` 这类占位符书写，由 `scripts/render_report.py` 替换为实际值（同时保留占位符源文件）；校验时检查渲染后的报告不含未替换的占位符。
   - 接入 `run_all.py` 最后一步；不一致时以非零码退出。
5. **需求追踪矩阵**：`export_handoff.py` 现有 `traceability`（需求 → 功能块/检查/测试）扩展为需求 → 计算步 → 器件 → 规则 → 测试，导出到 `report_tables.md` 表 A。

**验收标准**
- [ ] `calc.json` 每一步都有 `inputs`，且每个 `source` 能解析到实际存在的字段（写测试遍历校验）。
- [ ] `--stale` 对电感、MOSFET、`inductor_ripple_ratio` 三个例子给出合理的影响清单（写进测试的期望集合）。
- [ ] 人为改坏 `bom_module1.csv` 的一个立创编号或 `boost_params.h` 的 `CV_KP`，`check_consistency.py` 能报错并指出位置。
- [ ] 基线数值不变（1.4 节）。

### T4　规则检查（SDRC）升级

**为什么做**
现在 86 条规则只有 PASS/WARN/FAIL 和一句说明；规则的依据、严重度、适用条件没有结构化，报告里难以引用；`check_design.py` 即使有 FAIL 也以 0 退出，无法作为自动门禁；缺少数据时处理不统一——有的规则写成 `x is not None and …` 判 FAIL（把“缺数据”和“设计错误”混为一谈），有的规则被 `if tvs:` / `if ldo:` / `if drv:` 包住，器件未选上时**整条规则不出现**（静默遗漏）。
参考：fxp/ee-skills（531 条规则，每条带 severity/rationale/sources/verify，独立审计约 83 % 原样正确）、oaslananka/kicad-mcp-pro（缺少输入时判 `NOT_ASSESSED`，“永不静默 PASS”）、CircuitLM（Critical/Major/Minor/Warning 分级）。

**做什么**

1. **规则元数据** `knowledge/sdrc_rules.json`，每条规则（含 SR10-*/SR11-* 这类按类别展开的规则，用通配 `SR10-*` 描述）：
   ```json
   {"id": "SR30", "layer": "protection", "severity": "critical",
    "title": "阈值次序 Vo < OVPsw < OVPhw < TVS VBR,min",
    "rationale": "保护层级必须由软到硬依次动作，否则 TVS 会在正常/软件保护前导通",
    "source": "design_rules.md §5；SMAJ15A 数据手册 VBR 表",
    "verify": "automatic", "applies_when": "always",
    "closure_if_fail": "回 S4 调整 ovp 百分比或在 S6 更换 TVS"}
   ```
   - `layer`：requirement / rating / topology / control / thermal / sensing / protection / sourcing / firmware / model。
   - `severity`：critical（违反即不可交付）/ major / minor / info。
   - `verify`：automatic / simulation / measurement（仅能实测关闭的规则，如 SR73）。
2. **状态扩展**：`PASS / WARN / FAIL / NOT_ASSESSED / N/A`。
   - 缺少输入数据（如器件缺参数、仿真未运行）→ `NOT_ASSESSED`，**不得判 PASS**；
   - 规则不适用（如未选 PMOS 时的 PMOS 结温）→ `N/A` 并写原因。
   - 逐条检查 `check_design.py`：把 `x is not None and …` 中“x 缺失”的情况改为 `NOT_ASSESSED`（而不是 FAIL）；把 `if 器件:` 包住的规则改为器件缺失时输出 `NOT_ASSESSED`（而不是不输出）。
3. **`check_design.py` 改造**：读取 `sdrc_rules.json` 合并元数据；未在元数据中登记的规则 ID 报错（防止新增规则漏写依据）；`check.json` 每条结果带 layer/severity/rationale/source。
4. **退出码**（同时写入 `--help` 与 SKILL.md）：`0` = 无 FAIL 且无 critical/major 的 NOT_ASSESSED；`2` = 存在 FAIL；`3` = 无 FAIL 但有 critical/major 的 NOT_ASSESSED；`1` = 程序错误。`run_all.py` 根据退出码停止并提示回溯阶段。
5. **状态判定**：`ready_for_downstream`（无 FAIL、无 WARN、无 NOT_ASSESSED）/ `conditional_review`（无 FAIL，仅有 verify=simulation|measurement 的 WARN）/ `needs_rework`（有 FAIL 或 critical NOT_ASSESSED）。
6. **报告表**：`export_handoff.py` 的表 G 按 layer 分组，列出严重度、依据、出处。
7. **规则审计**（一次性）：逐条核对 `rationale/source` 是否与 `design_rules.md` 和数据手册一致，结果写入 `knowledge/sdrc_audit.md`（审计人、日期、发现的问题与修改）。

**验收标准**
- [ ] 全部规则都有元数据；未登记规则会使 `check_design.py` 报错退出。
- [ ] 构造 3 个测试：①删除某器件的 `isat_a` 参数 → 相关规则 `NOT_ASSESSED`、退出码 3；②把 `ovp_hw_pct` 调到大于 TVS → SR30 FAIL、退出码 2；③基线 → 退出码 0 且状态 `conditional_review`。
- [ ] `check.json` 与表 G 中每条规则带严重度与出处。
- [ ] 基线 PASS/WARN/FAIL 计数不变，或变化均有说明。

### T8　skill 规范化与评测

**为什么做**
依据 Agent Skills 规范与官方指南（agentskills.io：specification、best-practices、evaluating-skills、optimizing-descriptions、using-scripts；anthropics/skills 的 skill-creator）：
- 易错点（gotchas）应放在 SKILL.md 而不是埋在参考文件；
- description 要说明“做什么 + 何时用”，覆盖用户不点名领域的说法，并写明不适用场景，以提高触发准确率；
- 应有 `evals/`：任务评测（有/无 skill 对比）+ 触发测试（应触发与“擦边不应触发”各 8–10 条，各跑 3 次）；
- 脚本应非交互、有 `--help`、数据走 stdout、诊断走 stderr、退出码有文档。

**做什么**

1. **SKILL.md 增加“最常见的 8 个坑”**（每条一行，链接到 design_rules.md 详细条目），从 `design_rules.md §9/§9.1/§9.2` 提炼，例如：
   - 用输出电流 0.5 A 而不是输入/电感电流约 1.5 A 选器件；
   - MOSFET 导通电阻用 10 V 规格（5 V 驱动应看 4.5 V 规格）；
   - 驱动器 UVLO 只看典型值（UCC27517 最大 4.65 V，5 V−5 % 可能不启动）；
   - 陶瓷电容不计直流偏压降容（1206/25 V/X5R 在 12 V 下约剩 27 %）；
   - 电流放大器失调用 Vcm=0 规格（INA180 在 12 V 共模下 500 µV）；
   - 声称非同步 Boost 能短路恒流 / 关 PWM 等于断开输出；
   - 用 CCM 平均模型结论宣称轻载（DCM）稳定；
   - 电子负载 CC 模式测电源 CC 模式。
2. **description 改写**（≤ 1024 字符）：中英双语关键词（boost converter, CC/CV, component selection, LCSC BOM, power supply system design, STM32）；“Use when…” 句式；覆盖不点名的说法（如“5V 升 12V 的电源怎么设计”“帮我选电感和 MOS 管”）；写明**不负责**：原理图绘制（模块 B）、PCB 布局（C）、固件编写（D）、降压/隔离拓扑。
3. **`evals/` 目录**：
   - `evals/trigger_queries.json`：10 条应触发（含中英文、不点名领域的说法）+ 10 条擦边不应触发（如“写 STM32 的 PWM 初始化代码”“设计一个 Buck 降压电路”“画这个电源的 PCB”“解释 LDO 原理”）。说明运行方法：在 Codex 新会话中逐条输入（不加 `$`），记录是否加载了本 skill，每条 3 次，统计准确率，结果写 `evals/trigger_results.md`。
   - `evals/evals.json`：5 个任务（课程规格全流程；改需求为 15 V/0.4 A；指定不合规器件 UCC27517；要求加入库中没有的器件；不可行规格），每个任务写可检查的断言（如“selection.json 中 gate_driver 不是 UCC27517 且给出 UVLO 原因”“未编造立创编号”“SDRC 无 FAIL”）。说明有/无 skill 各跑一次并对比。
4. **脚本规范**：所有 `scripts/*.py` 支持 `--help`（argparse 已有的补齐说明与退出码）；诊断信息改到 stderr；`check_design.py` 退出码与 T4 统一；在 SKILL.md 列出各脚本退出码。
5. **黄金回归测试** `scripts/test_golden.py` + `tests/golden/`：保存基线的 `calc.json`、`selection.json`（只保留入选结果）、`check.json` 摘要与关键数值；测试从零运行后逐项比对（浮点相对误差 1e-6），差异时打印字段路径。修改设计逻辑导致基线变化时，必须同时更新黄金文件并在提交说明中解释。
6. **时效数据**：`parts_db.json` 的价格/库存字段增加 `checked_at`（日期）；SKILL.md 的 S9 增加“采购前在立创商城复核库存与价格”的提醒。

**验收标准**
- [ ] SKILL.md ≤ 500 行；8 个坑在正文中可见。
- [ ] 触发测试准确率 ≥ 85 %（20 条 × 3 次），结果文件入库。
- [ ] `evals.json` 5 个任务有断言与一次有/无 skill 的对比记录。
- [ ] `python -m unittest test_tools test_golden` 全部通过。
- [ ] 所有脚本 `--help` 可用并写明退出码。
