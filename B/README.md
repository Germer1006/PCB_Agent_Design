B 模块负责把系统需求或上游方案整理为可检查、可交接的原理图设计。当前文档优先定义职责、设计流程、数据约定、检查规则和后续实现路线。

## 设计范围

B 原理图设计的目标模块包括：

- Boost 功率级；
- 驱动与采样电路；
- MCU 最小系统；
- 调试和外部接口；
- 过压、过流、占空比限幅等必要保护。

首轮离线演示使用课程参考指标和抽象元件，主要验证数据结构、模块连接、检查、布局和交接流程。抽象元件不代表已经确认具体型号、封装、供应信息或可制造性。

## 推荐实施顺序

1. 冻结 `schematic-ir-0.1` 的最小 JSON Schema。
2. 建立简化 Boost 正常样例和故障样例。
3. 实现离线输入校验、连接检查、布局评分和受控修复。
4. 从同一份 JSON 生成 BOM、连接表、接口表、检查报告和需求追踪报告。
5. 替换为有资料依据的真实器件并执行完整回归检查。
6. 独立验证嘉立创 EDA 适配器，再接入真实原理图工程。

## 版本与交付原则

- JSON 是原理图中间数据的权威来源，CSV 和 Markdown 报告由 JSON 生成。
- 每次电路、参数或接口修改都应增加设计版本，并重新执行检查。
- 交接文件必须绑定设计版本，不能使用无法确认版本的反馈。
- 未验证、延期、推断和失败项必须在报告中明确标记。
- 没有真实 EDA 读回或检查证据时，不声明已经完成嘉立创 EDA 自动绘图。
