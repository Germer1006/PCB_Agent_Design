## 2. 当前使用什么输入

无需等待 A 的方案。首个本地样例使用课程参考目标，并记录为“参考设计输入”，不表示全组最终系统方案已冻结。

| 内容 | 首个样例的取值或处理方式 |
|---|---|
| 输入电压 | 5 V，允许偏差 ±5%，即 4.75–5.25 V |
| 输出参考目标 | 12 V、0.5 A、约 6 W；首轮只验证简化电路流程，不宣称已实现恒流恒压控制 |
| 开关频率 | 使用课程建议的 100 kHz 作为样例输入，并保留可配置字段 |
| 控制器 | 抽象 32 位 MCU 功能模型，暂不绑定具体型号或真实引脚号 |
| 首轮模块 | 输入、Boost 功率级、输出、基础电压采样、驱动与 MCU/PWM 接口 |
| 后续扩展 | 输出电流采样、完整 MCU 最小系统、调试、过压/过流、占空比限幅及需要的其他保护 |
| 器件状态 | `abstract`；保留功能、引脚、电气类型、关键约束；型号、封装、采购信息不伪造 |
| 来源 | 当前课程 DOCX、本地参考输入、用户确认的设计规则；各自保留引用 |

“抽象元件”指先用一个表示功能的器件模型跑通流程。例如先定义“具有电源、PWM、ADC 和调试引脚的 MCU”，之后再选具体 STM32 并核对每一个引脚。抽象模型不是可采购元件。

简化样例未覆盖的课程要求必须标为 `deferred` 并给出扩展任务；不能删除这些要求后宣布整个项目通过。

## 3. B1：先把数据标准和样例做实

### 3.1 最小权威数据

JSON Schema 是程序检查 JSON 格式和必填项的规则文件。它负责发现“字段缺失、类型错误”；电气连接是否正确仍由检查器判断。

首版 `schematic-ir-0.1` 至少冻结以下含义：

| 对象 | 必须表达的信息 | 必查约束 |
|---|---|---|
| 版本与范围 | `schema_version`、`project_id`、`design_version`、`completion_scope`、执行模式 | 不支持的版本明确拒绝；离线抽象范围不能冒充真实 EDA |
| 需求 | 需求 ID、数值、单位、范围、来源、适用范围与状态 | 数值与单位分开；缺值用 `null` 及原因，不能把“待确认”当数值 |
| 页面 | 页面 ID、名称、顺序和尺寸/标准坐标系 | ID 唯一；不能引用不存在的页面 |
| 模块 | 模块 ID、职责、元件与接口引用 | 引用存在；元件归属不能互相矛盾 |
| 元件 | 位号、功能/类别、元件库记录与版本、抽象/真实状态 | 位号唯一；真实与抽象不能混淆；真实器件须有证据状态 |
| 引脚 | 所属元件、引脚号、名称、电气类型、必接性、电压域和关键约束 | 同一元件引脚号唯一；未知类型显式记录；不能默认当被动引脚 |
| 网络 | 网络名、类型、所连元件与引脚、允许的供电/信号域 | 每个引用有效；普通引脚只能归属一个电气网；跨页标签同义 |
| 接口 | 来源、目标、网络、方向、有效电平、范围和采样换算等适用字段 | 与真实连接一致；不适用字段给出原因 |
| 布局 | 页面、元件与模块位置、方向、外框、标签和需要评分的连线几何 | 坐标合法；没有外框不能可靠检查重叠；没有连线路径不能虚构交叉次数 |
| 检查与问题 | 规则 ID、严重度、位置、证据、修复权限和解决状态 | 未执行与通过分开；关键未知项不得静默通过 |
| 假设与风险 | 假设内容、依据、影响、待验证项 | 抽象器件未验证的字段始终可见 |
| 运行与历史 | 状态、修复计数、动作结果、输入版本、变更和检查点 | 暂停恢复保留计数；派生文件绑定同一设计版本 |

首版允许在专门的扩展对象中添加字段。模型输出的未知顶层字段、拼错字段和不存在的版本应报错，避免程序悄悄忽略。破坏性修改升级 Schema 并提供迁移说明；迁移测试随实际版本变化增加。

网络的权威连接只保存元件和引脚引用；引脚电气类型从元件定义读取。缓存的源/接收端数量必须重算，不能直接相信模型给出的数字。

### 3.2 首个正常样例应包含什么

- [ ] 需求快照和每个数值的来源。
- [ ] 输入连接器、输入/输出电容、电感、开关器件、整流二极管、输出连接器。
- [ ] MCU 功能模型、驱动功能模型、供电与地参考、PWM 控制路径、默认关断路径。
- [ ] 电压分压与必要的采样接口，ADC 允许范围及最坏情况计算条件。
- [ ] 明确的 Boost 网络：VIN 接电感输入；电感另一端、开关器件漏极、二极管阳极构成 SW；二极管阴极接 VOUT；开关器件源极回到规定参考地。
- [ ] 串联器件两端使用不同网络。例如栅极电阻不能被同一网络短接；分压上、下电阻不能把 VOUT、ADC 与 GND 直接并成一网。
- [ ] 电源输入有来源，包含合法外部供电声明或抽象稳压功能；不能只写一个 3V3 标签就认为 MCU 已供电。
- [ ] 至少一页总览、全部元件坐标、符号外框与能追踪的连线/标签。
- [ ] 抽象元件库子集和锁定清单；缺真实型号、封装与供应信息的风险说明。
- [ ] 对完整 CC/CV、电流采样、调试与保护等未覆盖项的逐项 `deferred` 记录。

不要把主规范中的局部 JSON 片段直接复制后当正常样例：片段为解释字段而省略了内容，正常样例必须能独立通过引用与范围检查。

## 4. B2：把离线流程跑通

### 4.1 程序执行顺序

1. 读入需求、样例和锁定的库记录，建立输入快照与工作副本。
2. 校验 Schema，再检查引用、单位、版本与需求冲突。
3. 规划或读取模块与接口，形成元件—引脚—网络结构。
4. 执行连接、电气约束、需求覆盖和布局检查。
5. 对明确可修复问题执行最小修改；关键判断暂停并保存现场。
6. 每轮修改后执行回归，保留修改前后差异、检查结果与计数。
7. 通过后从同一 JSON 生成派生文件；未通过时仍保存失败报告，不能标为成功交付。
8. 生成清单 `manifest.json`，声明完成范围、已生成/未生成文件、版本、检查状态与证据路径。

固定样例经过程序检查与修复，只能证明执行层闭环。若要称为“原理图设计智能体”，还需证明模型能从需求生成结构化规划/动作、程序能校验并执行动作、模型能依据真实工具结果继续判断。不得把一份固定电路模板和规则脚本当作已验证的完整模型智能体。

### 4.2 5 轮到底如何计算

- 初始检查为检查 0，不算修复。
- 一组修复动作加一次复查为 1 轮；电气修复最多 5 轮，布局调整独立最多 5 轮。
- 复查、重启、暂停恢复和切换子流程都不得将计数清零。
- 布局调整不改变电气连接、器件值、模块接口和保护逻辑；调整后核对电气结构保持一致。
- 第 5 轮仍失败时保存剩余问题并停止该自动修复流程。仅剩非阻塞普通问题可附说明结束；仍有 Error、关键未知项或风险判断则暂停。
- 到达上限后的处置不再修改设计；需要新的实质修复时，必须在明确记录的新任务范围或用户决定下继续，不能偷偷开始第 6 轮。
- 后续整合的 PCB 反馈另有最多 5 轮限制，当前不借用此计数开展真实团队联调。

### 4.3 检查器与评分器的实现底线

首批连接检查覆盖：引用不存在、位号冲突、必接引脚悬空、供电缺失、普通输出相连、电压域冲突、ADC 超量程、开关节点误接、驱动/关断路径以及本轮范围内的必需模块缺失。

不能只数网络中有没有 `output` 就判断输入有无驱动。串联电阻后的引脚可能存在合法路径；分压和滤波需结合器件功能与参数判断。电容不能在直流供电检查中当作导线，二极管和晶体管也不能无条件短接全部引脚。

布局采用主规范的七项权重，默认 80 分参考线。严重重叠、遮挡、越界或关键连接不可追踪属于阻塞项，即使评分超过 80 仍失败。缺少外框、连线路径或标签数据时，对应指标写 `not_evaluated`，不能捏造分数，也不能无说明地重新分配权重。

### 4.4 离线输出

| 文件 | 验收重点 |
|---|---|
| `schematic.json` | 唯一权威数据，含最终结构、问题、假设和版本 |
| `project_library_subset.json`、`library_manifest.json` | 仅包含本轮所用记录，锁定版本与证据状态 |
| `bom.csv` | 位号/数量不重复，抽象与真实状态明确 |
| `connections.csv` | 每个端点能返回 JSON 中的实际元件/引脚 |
| `interface_table.csv` | 网络、方向、量程、极性和适用换算信息一致 |
| `check_report.md` | 规则覆盖、通过/失败/未执行、轮次和剩余问题 |
| `requirement_traceability.md` | 每项需求对应证据，区分已覆盖、延期、未验证与失败 |
| `assumptions_and_risks.md` | 抽象器件限制、关键未知项和后续动作 |
| `change_log.md`、运行日志、检查点 | 可追溯输入、动作、返回值、计数与恢复位置 |
| `manifest.json` | 所有文件的设计版本、内容摘要/校验值、完成范围与能力限制 |

文件应先写入临时输出目录，全部生成并通过一致性检查后，再将这一组标记为本轮有效结果。部分生成失败时保留失败现场，不用半套新文件覆盖上一套有效结果。

离线阶段不要求假造嘉立创EDA源工程或原理图 PDF。尚未生成的文件在清单中明确注明；若额外生成 SVG/PDF 预览，应标注为离线预览，不能称为真实 EDA 导出。

## 5. B 自己就能完成的验收场景

下面是待实现的行为验收标准。每例保存输入、实际输出、预期对比和日志；测试报告中只有真实执行的用例才能标为通过。

| 编号 | 场景 | 预期行为 |
|---|---|---|
| B-T01 | 正常抽象 Boost 样例 | 范围内结构检查通过，生成同版本输出；完整课程未覆盖项仍显示延期 |
| B-T02 | 网络引用不存在的元件或引脚 | 明确定位并报 Error；不猜测替换，不生成成功状态 |
| B-T03 | 同一普通引脚同时属于两个不同网络 | 报数据冲突；不能靠重复输出掩盖短接 |
| B-T04 | 已确认连接表明确规定的供电连线漏接 | 仅在证据足够、没有拓扑歧义时补回；日志可见修复与复查 |
| B-T05 | 两个普通输出直接相连 | 报 Error 并暂停；不能任意断开一个输出或改成被动类型 |
| B-T06 | ADC 最坏情况电压超过允许范围 | 输出计算依据与超量程错误；不得擅自提高 ADC 额定值 |
| B-T07 | MCU 采样直接接到 SW | 报关键误接并暂停，不能凭网络重命名宣称解决 |
| B-T08 | 输出经串联电阻连接输入 | 根据合法路径判断，不能因局部网络没有直接输出而误报悬空 |
| B-T09 | 已知可修问题修复后通过 | 提前结束，记录实际轮次，不强行跑满 5 轮 |
| B-T10 | 人工构造每轮都有剩余问题的修复情形 | 最多执行 5 次修复；第 5 次失败后停止，不存在第 6 次动作 |
| B-T11 | 第 3 轮后暂停并重启恢复 | 从已保存计数恢复，剩余最多 2 轮；原输入与版本可追溯 |
| B-T12 | 高评分但存在严重重叠/越界 | 仍失败；布局调整保持元件与引脚的电气连接不变 |
| B-T13 | 缺少布局外框或连线路径 | 对应检查显示未执行及缺数据原因，不能输出虚构满分 |
| B-T14 | 抽象元件缺少真实型号与封装 | 允许按抽象范围验证，但不允许 `ready_for_pcb` 或“可制造”结论 |
| B-T15 | 生成期间失败、派生文件被手改或版本不一致 | 检测失败/校验变化，保留上一套有效结果；重新从 JSON 生成 |
| B-T16 | 本地旧版本反馈样例 | 拒绝套用到当前设计，报告版本差异；不开展真实 C 联调 |
| B-T17 | EDA 不可用或返回失败 | 继续允许的离线工作，真实能力记未验证；不把失败写成成功 |
| B-T18 | 参考输入的关键目标互相冲突 | 列出来源和影响，暂停关键设计；不静默覆盖 |
| B-T19 | 真实器件或元件库版本替换 | 校验引脚、额定值和证据，重新跑连接、布局、BOM 与需求回归 |
| B-T20 | 模型提出非法动作或工具只部分成功 | 程序拒绝非法动作；依据实际返回值保留现场，不假定动作完成 |

## 7. B4：验证嘉立创EDA真实能力

在独立测试工程验证主规范第 28 节的最小动作：读取、复制、放符号、连网、改字段、保存、导出 PDF/BOM、执行可用检查和恢复。

每项至少记录：客户端版本、使用的真实接口及其依据、输入、返回值、读回结果、文件路径、失败原因与恢复方式。不能仅根据论文、应用已安装、扩展名猜测或模型记忆宣称接口可用。

某项不支持时，记录 `unsupported`；尚未尝试时写 `not_tested`；实际失败时写 `failed`。若只能离线导出数据，则报告实际能力边界，保留继续接入所需的适配器接口。

完成最小动作验证后，再把 B3 的设计映射到 EDA。应读回元件、引脚、网络和布局，比较映射前后差异，并保存实际工程、PDF/BOM 与检查结果。界面看起来成功不能替代文件读回和连接核对。
