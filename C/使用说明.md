# KiCad 两层 PCB 草稿与交付检查

本工具从已完成的原理图/完整网表生成布局布线草稿，并检查实际原生文件。默认面向小型电路；当前启发式布局和栅格布线不保证收敛，也不自动证明电源性能。

## 环境与输入

需要 Python 3.10+、KiCad CLI、匹配的 `pcbnew` Python 和实际封装库。通过 PATH、`KICAD_CLI` 或 `--kicad-cli` 指定 CLI；程序会寻找能导入 pcbnew 的 Python。Windows 可双击 `启动自动设计.cmd` 使用 Tk 窗口，复杂约束与资源预算使用命令行。

支持现代 `.kicad_sch`、完整 KiCad XML/`.net` 网表和 B 的 `B-to-C-1` 格式 `project_input.json`。完整分层网表不会因含子页而被拒绝；提供源原理图时复制所有子页并执行原生一致性检查。只有网表时执行逐焊盘网络读回，报告明确不包含原生原理图一致性。

原理图与封装必须能由所选 KiCad 版本读取。随附 `demo/Boost练习.kicad_sch` 是 KiCad 10 格式，KiCad 9 不可直接打开。不要改写文件版本头冒充兼容转换。原有 `生成示例` 是历史示例，不是当前输入的验证记录。

缺少封装、引用或引脚不存在、源规则被放宽、混用约束版本等情况会停止，不猜封装、不删器件。保留输入项目的 `.kicad_pro`、`.kicad_dru`、库表和本地库。

## 从 B 交接运行

以下命令从仓库根目录执行，替换示例路径：

```bash
python B/prepare_pcb_input.py A_output/design_spec.json B_output/full.xml --schematic B_output/main.kicad_sch --output handoffs/B_to_C_r2
python C/auto_pcb.py handoffs/B_to_C_r2/project_input.json --output C/results --size 60 45 --attempts 2 --target draft
```

直接读取完整网表也可以，但应提供同版本的约束与源原理图：

```bash
python C/auto_pcb.py B_output/full.xml --source-schematic B_output/main.kicad_sch --constraints B_output/pcb_constraints.json --output C/results
```

默认最多 30 器件、150 焊盘、650000 栅格单元。更大设计显式使用 `--max-components 100 --max-pads 300` 等预算；上限为 200 器件、1500 焊盘和 4000000 栅格单元。预算放宽仅允许尝试，不证明能自动布通。板尺寸为 8–100 mm，每次最多 8 个候选，单次布线超时由 `--router-timeout` 控制。

默认信号宽 0.25 mm、功率宽 0.45 mm、间距 0.20 mm。它们是软件初值，必须按实际铜厚、载流与板厂能力确定；不能低于输入项目已有的更严格规则。命令行范围为 0.15–5 mm。保留更严格的孔距等规则；禁止通过忽略 DRC 或排除错误取得通过。

## A/B/C 结构化布局约束

格式见 [JSON Schema](../schemas/pcb-constraints-1.schema.json)。只接受已定义字段和真实器件/焊盘：

| 字段 | 执行的检查 | 范围限制 |
| --- | --- | --- |
| `groups` | 关联器件中心包围盒的对角跨度 | 不等于实际功率环路面积 |
| `pad_pairs` | 两个真实焊盘的直线距离 | 不等于走线长度、电感；去耦/Kelvin 对必须同网 |
| `fixed` | 器件的固定位置与正交旋转 | 不可由优化器挪动 |
| `regions` / `keepouts` | 完整器件包络位于允许区/避开禁放区 | 只检查器件，不创建铜层禁布区 |
| `footprints` | 分位号的候选/已验证记录 | 已验证必须对应实际封装并含料号、审核者、依据 |
| `upstream` / `required_reviews` | 保留上游问题及必要人工审核 | C 不替 A/B 关闭问题 |

定量限值须有本设计依据；没有依据时填 `null`。程序会输出实测距离并标为 `not_assessed`，不自动转换成通过。检查实际驱动回路、去耦回流、采样 Kelvin 分支、SW 铜面积与电流回路仍需工程审核。

## 可选策略与外部布线

`--strategy strategy.json` 输入模型给出的网络顺序/同网焊盘配对，或显式使用 `--model` 调用已配置 Codex。未知网络、跨网配对等会拒绝；在线请求失败时记录原因并回退本地策略。模型建议不构成审核。

可用 `--freerouting-jar /path/freerouting-2.x.jar` 显式指定官方 Freerouting 2.x JAR，需要 Java。程序不自动下载 JAR，会记录哈希与真实命令、保留功率铜、重布控制和 GND，并原生复查；结果更差则恢复。`--ground-planes` 可增加并填充地平面。GND 细线、过孔与平面连接仍需按实际回流/载流审核，不能因自动布通而认可。

## 输出与可打样状态

| 文件 | 内容 |
| --- | --- |
| `project/` | PCB、显式规则、完整输入网表、可用的源原理图/子页、本地符号库与冻结封装库 |
| `DRC.json` | KiCad 原始 DRC，包含所有走线、警告、未连接及可用的一致性检查 |
| `readback.json` | 原生读取器件、全部焊盘网络、层数、UUID 后与完整网表比较 |
| `layout_check.json` | 定量几何检查与待评估项 |
| `verification.json` | 本次验证记录及工程文件哈希，用于识别旧结果 |
| `execution_status.json` | 布线完成、DRC/读回和打样状态分别记录 |
| `release_status.json` | `prototype_ready`、`production_ready` 与当前阻塞项 |
| `roundtrip_check.json` | ZIP 解压后对真实工程再执行 DRC/读回的记录 |
| `delivery.zip` | 独立可解压工程与一致的检查记录，不含失败候选与临时工程文件 |
| `设计报告.md`、`布局与布线.json`、`preview/` | 报告、实际原生走线/器件数据与可用的预览 |

`routing_complete` 表示原生检查无未连接、读回通过，不承诺 DRC 为零。草稿命令返回 0 表示原生 DRC 通过、读回一致且没有已失败的几何约束；空限值和其他待评估项依然存在。`--target prototype` 只有 `prototype_ready=true` 才返回 0。生成/打样检查未完成返回 2，执行失败返回 1。

打样放行还要求：上游状态可交接且无问题、全部实际封装核实、显式规则与几何检查合格、工程审核绑定当前文件、解压复查完成。`production_ready` 固定为 false，不能替代上电、稳定性、纹波、效率、温升与量产资格验证。

## 审核现有工程并重新打包

`RUN_DIRECTORY` 使用程序打印的运行目录：

```bash
python C/release_check.py RUN_DIRECTORY
python C/release_check.py RUN_DIRECTORY --write-review-template review_draft.json
```

空模板故意不通过。只有真实完成电气、功率布局、采样回流、机械/工艺和目标 GUI 重开等审核后，才能填写审核者、日期、逐项结论与证据。CLI 解压读回不等于 GUI 重开。审核不能豁免已失败的定量限值。

```bash
python C/package_project.py RUN_DIRECTORY --review completed_review.json --target prototype
python C/release_check.py RUN_DIRECTORY
```

此命令复查原有工程并更新交付包，不重新布局或生成 UUID。PCB、网表、约束、规则或库发生改变时，哈希使旧证据失效，应重新验证和审核；本工具当前没有任意手工改板后的自动补证入口，不能手改 `verification.json` 以复用旧记录。

## 回归测试

```bash
python -B -m unittest discover -s C/tests -v
```

原生测试使用临时完整网表，真实调用 CLI 和 pcbnew，检查封装库冻结、ZIP 解压、错误输入与审核失效。无 KiCad CLI 时明确跳过，不把纯软件测试称为 EDA 复查。
